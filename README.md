# POTS / IBS 有效资金与异常账户监控

这套监控只回答两个问题：项目还有多少真实 USDT 支撑，以及哪些账户正在以异常方式从 LP 持续取走 USDT。

## 1. 有效资金监控

主工作流 `POTS Effective Funds Monitor` 每 5 分钟检查一次链上状态，默认每 60 分钟向 Telegram 汇报一次，并与**上次报告**直接比较，不再使用 24 小时或 7 天窗口。

有效国库只计算：

```text
IBS/USDT LP 中的 USDT 储备
+ RBS Contract 中的 USDT
+ Safety Treasury 中的 USDT
```

IBS 自身不计入国库资产。每次报告显示：

- LP、RBS、Safety 和国库 USDT 当前值，以及相对上次报告增加或减少多少；
- 按本次报告间隔内的下降速度，静态外推国库和 RBS 还能支撑多少天；
- IBS 总供应量、流通量代理和本次净增发量；
- 池内小额现价；
- 扣除 LP 自己持有的 IBS 后，全部池外 IBS 一次卖入当前 LP 可取出的 USDT，以及平均清算价；
- 国库按池内现价能覆盖多少池外 IBS、覆盖率和资金缺口。

以下情况不等常规报告，会立即通知：

- RBS 或 Safety 余额发生变化；
- 国库变化达到 10,000 USDT；
- IBS 总供应量变化达到 1 IBS。

可以在 `Settings → Secrets and variables → Actions → Variables` 调整：

- `POTS_FLOW_REPORT_MINUTES`：常规报告间隔，默认 60 分钟；
- `POTS_IMMEDIATE_TREASURY_USDT`：国库即时变化门槛，默认 10,000 USDT；
- `POTS_IMMEDIATE_SUPPLY_IBS`：IBS 供给即时变化门槛，默认 1 IBS。

## 2. 异常账户监控

普通买入、普通卖出和单笔大额买卖不再发送 Telegram。账户提醒只保留以下证据较强的异常行为：

- 已知平台或协议地址直接卖出；
- 本池内出现可重复的短周期正利润闭环；
- 协议来源 IBS 被持续卖出，并从 LP 取走较多 USDT；
- 高频买卖同时对 LP 形成显著净 USDT 流出；
- 外部转入的未知成本筹码被高频卖入 LP。

同一个地址只会在首次达到异常条件、异常类型升级、累计新增 10 次卖出，或距上次提醒达到 24 小时时再次通知。近 6 小时异常账户榜也只保留“高频并且对 LP 净取走 USDT”的地址，不把高频净买入者列为抛压账户。

“疑似套利”是行为证据，不是最终身份判断；“协议来源异常变现”也不能仅凭链上记录定性为平台老鼠仓。确认关联关系仍需要资金上游、共同出资地址、合约权限或链外证据。

## 运行与安全

仓库 Secrets 需要：

- `BOT_TOKEN`：Telegram Bot Token；
- `CHAT_ID`：Telegram 群 ID；
- `BSC_RPC`：BNB Smart Chain Mainnet RPC。

监控只读链上数据，不需要钱包私钥。余额、储备、总量和价格固定在同一个确认区块读取。

## 指标边界

- LP 的 USDT 变化包含用户交易影响，不等于项目经营利润；
- 池内现价只适合小额成交，不能代表全体持有人同时退出的价格；
- 平均清算价采用恒定乘积 AMM 和当前储备静态估算，未计算其他池、抢跑、滑点保护或未来流动性变化；
- 国库覆盖率是可见链上 USDT 的风险代理，不是项目承诺兑付或审计净值；
- 可支撑天数假设本次报告间隔内的净消耗速度持续，仅用于趋势预警。
